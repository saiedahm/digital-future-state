Research status — not a partnership list.
These 120 entries are candidates, not confirmed partners and not proof that every company offers a public API. Official documentation or corporate portals are provided for discovery; access, supported products, geographic eligibility, pricing, approval and commercial terms must be verified before implementation. We will use official APIs, OAuth/OIDC, SDKs, webhooks, standard federation protocols or approved intermediaries where offered. We will not bypass authentication, scrape restricted systems, or reverse-engineer private endpoints. Where no authorized API is available, use a deep link, user-controlled export/import, a formal partnership request or omit the integration.
Recommended integration order
  1. Start with the platform's own secure account and verify email, recovery, and session handling.
  2. Implement one identity provider end-to-end (Google or Microsoft) with correctly configured redirect URLs and consent.
  3. Add business API connectors only after a user or organization explicitly authorizes them.
  4. Request formal partner access for government, banking, telecom, travel inventory and restricted commerce systems.
  5. Keep secrets server-side, use least-privilege scopes, validate webhook signatures, log consent, and provide disconnect/delete controls.
