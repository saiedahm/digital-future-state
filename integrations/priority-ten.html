PHASE 1 · TEN PRIORITY SERVICES

Ten services. One clear integration plan.

We will connect services through their official APIs, OAuth/OIDC flows, SDKs or approved partner programs where available. Each connection must be configured and tested before it can be marked live.

Honest status: this page is the implementation roadmap, not proof that these providers have approved or connected to DIGITAL FUTURE STATE. Google and Microsoft sign-in buttons already exist in the account page, but they still depend on the correct Supabase and provider configuration. Payment and other APIs likewise require their own accounts, credentials, permissions and end-to-end tests. Never put private API keys in browser code.

The first ten

Account sign-in

Enable Google sign-in for a DIGITAL FUTURE STATE account using the existing Supabase authentication flow.

Safe implementation order

  1. Authentication: verify Supabase project URL, public anon key, Google and Microsoft provider settings, exact redirect URLs and email confirmation behavior.
  2. Payments: finish Stripe sandbox tests first; consider PayPal only as a separate, independently tested integration.
  3. Useful services: prioritize the API that supports a confirmed platform feature, and keep credentials server-side wherever required.
  4. Release gate: only label a service “Live and tested” after a real end-to-end test succeeds. Provider approval and credentials may be required before that is possible.
To continue the real connections: the next practical task is to check the project's Supabase authentication configuration and verify the Google/Microsoft redirect flow. No passwords or secret keys should be pasted into this public repository or into chat.
